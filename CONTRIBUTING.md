# Contributing

The goal is useful shared knowledge, not the largest possible unreviewed glossary.

1. Open an issue describing the concept or correction. Supply publicly accessible primary sources.
2. Check whether the idea is a new concept, a contextual name, a variant or a genuinely distinct move.
3. Write an original concise summary. Never paste private team playbooks, private conversations,
   personal data, copyrighted long passages, images or videos without publication rights.
4. Separate source-supported description from editorial interpretation. Scope evidence to claims.
5. Include exceptions, uncertainty, competition format and at least two decision alternatives.
6. Preserve abstract roles. Implementation coordinates/timings belong in consumer adapters.
7. New content starts `source-backed`, with reviewer fields null and `execution.ready: false`.
8. Run `npm run check`. Verify desktop/mobile layout, keyboard use, empty/error states,
   detail → related detail → Back/Forward, query restoration and deep links if UI changed.
9. Open a draft pull request. Obtain content/publication-rights review and technical review
   before merge. A passing test does not certify the rugby claim.

For a genuine expert review, identify the reviewer with their permission, record the date
and exact reviewed scope, and link the review discussion. Do not invent names or assert review
because a source is from an authoritative publisher. Initial data have not had that review.

Changes in released meaning require version changes. Never recycle IDs. Do not promote
`contextual` aliases to `synonym` just because search results are similar.

Contributions to code are MIT; original data are CC BY 4.0. External sources retain their rights.
